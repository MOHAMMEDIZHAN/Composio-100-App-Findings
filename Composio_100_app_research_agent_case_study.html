Easy wins

  • HubSpot, Twilio, Mailchimp, Shopify, GitHub, Notion, Airtable, Stripe, Apify, and Supabase have clear developer pathways.
  • These are strong initial toolkit targets because API documentation and credential creation are broadly accessible.

Outreach / review targets

  • Meta, Google Ads, Pinterest, WhatsApp, and Plaid need review or production-specific approval.
  • “Technically buildable” does not mean “commercially accessible without a customer relationship.”

04 / What was built

App Research Agent: a single-file, URL-driven research tool

The tool accepts an application URL, maps it to a structured app record, simulates an eight-step research workflow, displays the report, and exports Markdown or JSON.

Tool capabilities

  • URL matching: exact domain, subdomain stripping, base-domain fallback, path disambiguation, and substring fallback.
  • Built-in database covering 100 apps across the 10 requested categories.
  • Structured fields: auth, access, API, GraphQL, MCP, buildability, risks, pricing, webhooks, SDKs, gotchas, and evidence.
  • Exports: on-screen report, Markdown, JSON, and downloadable `.md` file.

Technical design

  • One `index.html` file with zero build step and no server requirement.
  • Client-side data only: no URLs or user data leave the browser.
  • Unknown URLs return a research template rather than a fabricated answer.
  • Designed for fast triage; verification workflow upgrades claims before publication.

05 / Process and human role

The workflow is designed to make uncertainty visible.

The agent handles repeatable collection and normalization. Humans decide when an evidence gap, access restriction, or high-impact action requires direct confirmation.

1. DiscoverResolve canonical docs, pricing, auth, API, and MCP sources.
→
2. ExtractWrite structured claims with evidence URL, date, and confidence.
→
3. Browser-useTest sign-up, developer console, token path, plan, and approval requirements.
→
4. Human checkResolve ambiguity, private docs, legal/commercial gates, and risky actions.
→
5. PublishLabel claims Verified, Partial, or Unresolved.

Agent handles

  • Consistent URL lookup and category classification.
  • Field extraction, source capture, and missing-field detection.
  • Large-scale table generation and exports.
  • Regression checks when documentation or price pages change.

Human needed when

  • Developer documentation is private or blocked by login.
  • App approval, partner status, business verification, or enterprise contract is required.
  • Claims conflict across sources or depend on current plan/account state.
  • An agent could create, delete, spend, message, trade, or expose sensitive data.

09 / Recommendation

Ship the agent with provenance and review states—not just answers.

The research is useful immediately for prioritization. It becomes dependable for production decisions only when it treats evidence and uncertainty as first-class output fields.

Build now

Self-serve apps with broad APIs and strong docs: GitHub, Notion, HubSpot, Twilio, Mailchimp, Shopify, Stripe, Apify, Supabase.

Build with caveat

Apps whose access changes by scope, plan or account: Slack, Pinterest, Google Ads, Shopify, QuickBooks, Plaid.

Route to outreach / review

Enterprise or weakly evidenced apps: DealCloud, Gladly, PitchBook, Fanbasis, Waterfall, LinkedIn Marketing.

Success criterion: a reviewer can understand the market patterns in two minutes; an agent can consume the records without parsing slides; and any claim can be traced to a source or explicitly labeled unresolved.
